# 计划：auto 模式自主性最大化（不牺牲硬边界）

- 日期：2026-10-14
- 状态：待评审（**纯配置层方案，无代码改动**；T2 为可选代码项，默认不做）
- 前提：`v1.1.0` 已发布并弃用；当前工作树准备 `v1.2.0`，`AI:no-box` 已修复；本文只谈自主性

## 0. 原则与红线（动不了的）

提升自主性 = **移除"审查层"**，而不是移除"执行边界"。以下硬边界一条不动：

1. **逃逸判定（已更新）**：提权、enforcing 沙箱逃逸、文件工具项目外写入 → 人工；沙箱 `off`/不可用的其余可审查 bash → AI（`aiGatesUnsandboxed` 出厂默认 true）。
2. **文件工具的项目外写入** → 人工（文件工具从不受沙箱约束，写出去就是真实写）。
3. **保护路径硬拦**（`.git/`、`.env*`、dotfiles、`.claude/{commands,agents}/`…），auto 无 `bypassProtectedPaths`。
4. **`denyRead` 秘密在内核层遮蔽**（bash 侧）。
5. **网络 deny-by-default**（`net:limit` 时）；项目配置只能收紧。
6. **分类器故障 fail-closed**（默认拦）。
7. **沙箱 = bash 的真实执行边界**（写限 `allowWrite` + scratch）。

**代价的统一表述**：所有 T0 项牺牲的都是"**软审查**"（分类器这道启发式闸门），硬边界零牺牲。真正的安全边界从来不是分类器。

## 1. 现状：auto 下谁决定什么

| 操作 | 谁决定 | 频率 |
|---|---|---|
| `read`/`grep`/`find`/`ls`（项目内） | 全自动 | 高 |
| Tier-1 白名单 bash（`ls`/`cat`/`git status`…） | 全自动 | 高 |
| **`write`/`edit`（项目内）** | **分类器** | **最高** |
| **非白名单 bash（项目内）** | **分类器** | **高** |
| 项目外 `read`/`ls`/`grep`/`find` | 分类器 | 中 |
| 项目外 `write`/`edit` | **人工**（本轮修复） | 低 |
| 提权 / 沙箱 off 的 bash | **人工** | 低 |
| `web_search` / 扩展 `tool` / `skill` | 分类器 | 中 |
| allowlist 外主机（`net:limit`） | 人工 | 视任务 |
| plan 批准 / `request_network_access` | 人工 | 低 |

结论：**弹窗与分类器调用的大头是"文件写入"和"非白名单 bash"**——自主性提升应集中在这两类。

## 2. 提升项与代价

### T0 — 立即可做：纯配置、零代码、硬边界零牺牲

#### T0-1 `write`/`edit`: `ask` → `allow` 　【推荐 ★★★】
- 做法：`modes.auto.permission.write/edit = "allow"`
- 收益：**频率最高**的一类操作零弹窗、零分类器调用（省 token + 延迟）
- 代价：
  - 项目内文件被**无复核**覆盖/写坏（少一道软审查）。缓解：git 回滚；保护路径仍硬拦；**项目外写入仍人工**；bash 仍过分类器+沙箱。
  - 残余风险：提示注入让模型篡改项目内脚本，之后由某次 bash 执行——与 **edits 模式同款**风险（edits 本来就 allow）。
- 硬边界：0 牺牲

#### T0-2 bash 按命令族的策略白名单 　【推荐 ★★★，逐条加】
- 做法：`"bash": { "*": "ask", "npm run *": "allow", "npm test*": "allow", … }`（Tier 0 放行，不调分类器）
- 收益：常用构建/测试/提交零弹窗零分类器
- 代价：这些命令族**完全绕过分类器**——但仍在**沙箱内**执行（写受限、网络按 allowlist、秘密遮蔽），逃逸仍人工。风险 = 放行族自身做想不到的事（`npm run *` 会执行 package.json 里的任意脚本——受沙箱+网络兜底）
- 语义提醒：策略按「拼接命令 + 每个 token + 别名」匹配；`*` 含 `/`；项目配置可再收紧
- 推荐：✅ 这是**最可控**的自主性杠杆——你逐条决定信任谁

#### T0-3 `skill`: `ask` → `allow` 　【推荐 ★★】
- 代价：技能是**指令内容**，可能指挥模型跑命令——但命令仍过 bash 门控。低风险

#### T0-4 `web_search`: `ask` → `allow` 　【推荐 ★★】
- 代价：query 是出站数据（模型生成的），理论上可当外泄信道；但模型能读到什么本身受控。低风险

#### T0-5 `tool`：**用模式白名单，不要全放** 　【谨慎 ⚠】
- 做法：`"tool": { "*": "ask", "<信任的工具>": "allow" }`
- 代价（若 `"*": "allow"`）：所有扩展/MCP 工具（**第三方代码路径**）的调用不受审——T0 里唯一建议克制的项
- 推荐：⚠️ 逐个放行你信任的工具

#### T0-6 `classifier.failClosed: false`（全局） 　【可选】
- 收益：分类器**故障**时转人工而非拦截（可用性↑；headless 仍拒）
- 代价：几乎为零（人工决定）；副作用是"分类器坏 → 每个 ask 都弹人工"
- 推荐：如果你常遇到分类器超时/报错，可开

### T1 — 数据层，代价明确，按需

#### T1-1 `sandbox.allowWrite` 扩容（如 `~/.npm`、`~/.cache`、`~/go`）　【⚠ 边界外挪】
- 收益：这些目录内的 bash 写入不再算"越界"→ 不弹人工
- 代价：**沙箱边界外挪**——这些目录内的写入完全不受限（例：`~/.npm` 可被覆盖 → 供应链风险）。同时 `sandboxAllowedRoots` 变大（逃逸判定更宽松）
- **绝对不要加**：`~/.ssh`、`~/.gnupg`、`~/.aws`、`~` 本身
- 推荐：⚠️ 仅在真实需要时、目录尽量窄

#### T1-2 网络 allowlist 扩容 　【⚠ 每个域名 = 外泄面】
- 收益：对应主机免弹窗
- 推荐：⚠️ 按需；日常 `net:limit`

#### T1-3 `network.askOnBlockedHost: false` 　【可选】
- 收益：allowlist 外主机**静默拒绝** → 零打断
- 代价：模型需要新主机时只能失败（或走 `request_network_access` 仍要人工）——能力↓换零打扰

### T2 — 代码级（默认不做）

#### T2-1 分类器"会话记忆"（一次放行 → 整族免审）　【❌ 不推荐】
- 代价：**泛化**——放行一次 `npm test` 就放行整个 `npm` 族，等于把分类器降级为"首次闸门"
- 结论：T0-2 的策略白名单是**更可控的等价物**，用它替代

#### T2-2 Tier-1 白名单扩容（改 `safe-command.ts`）　【谨慎】
- 代价：进白名单 = 永久免审；错一条 = 静默执行
- 推荐：仅加"确定性只读"命令，逐条过；用户级需求优先用 T0-2 策略表达

## 3. 推荐配置（可直接抄进 `~/.pi/agent/permission-mode/permission-mode.json`）

```jsonc
{
  "modes": {
    "auto": {
      "permission": {
        "write": "allow",          // T0-1：文件写入免审（保护路径/项目外仍拦/人工）
        "edit": "allow",           // T0-1
        "web_search": "allow",     // T0-4
        "skill": "allow",          // T0-3
        "tool": { "*": "ask" },    // T0-5：或逐个 { "*": "ask", "<tool>": "allow" }
        "bash": {
          "*": "ask",              // 其余 bash 仍走分类器
          "npm run *": "allow",    // T0-2：按你的信任逐条加
          "npm test*": "allow",
          "npm install*": "ask",   // 显式写出来表示"保持询问"（可省略）
          "git add *": "allow",
          "git commit *": "allow",
          "make *": "allow",
          "python -m pytest*": "allow"
        }
      }
    }
  }
}
```
改完需**重启会话或 `/reload`** 生效。项目配置仍可逐项收紧；`classifier.failClosed` 与 `network` 在顶层配置。

## 4. 代价的诚实总结

| 维度 | 影响 |
|---|---|
| **硬边界**（沙箱/保护路径/denyRead/逃逸→人工/网络默认拒） | **0 牺牲**（T0 全部；T1-1/T1-2 例外——它们是"重定义边界"，不是"取消执行"） |
| 软审查 | 项目内文件写入、白名单命令族、web_search、skill 不再复核 |
| 审计 | 分类器调用记录减少（策略放行不走模型）；bash 输出的 `<sandbox_violations>` 仍在 |
| 残余风险 | 提示注入下的项目内文件篡改（git 兜底）；被放行命令族的自身行为（沙箱+网络兜底）；`net:free` 时外泄面全开 |

**一句话**：T0 的每一项都是"**把分类器这道启发式闸门换成你已经显式表达的信任**"，硬边界一条不动。

## 5. 验证
1. 改全局配置 → 重启会话；
2. `auto` 下跑一轮真实任务，观察：文件写入零弹窗；`npm run build` 零弹窗；`curl evil.com` 仍被网络门/分类器拦；`sudo` 仍人工；
3. `/permission` 与 `pi config` 确认生效策略；
4. 项目配置收紧测试：在 `.pi/permission-mode.json` 里把 `write` 改回 `ask`，确认项目级仍能压过全局。

## 6. 落地状态（2026-10-14）

- T0 已提升为**出厂默认**（1.2.0）：auto 的 `write/edit/web_search/skill` 放行；常见构建/测试命令族进入 bash Tier 0；tool 保持 ask。
- T1 网络按合理范围进入出厂默认：GitHub CDN + NixOS hosts；`allowWrite` 未扩容（避免供应链/全局目录写入风险）；`askOnBlockedHost` 保持人工询问。
- T2-1（分类器会话记忆）不做：一次模型放行不泛化为整族免审。
- **`aiGatesUnsandboxed`**（出厂 auto 默认 true，自定义模式默认 false）：自定义 classifier 模式可将沙箱 off/不可用时完全可审查、非提权动作交给 AI；提权、enforcing 沙箱逃逸、不可审查 payload、保护路径和文件工具写越界仍人工/硬拦；脚本内容（有界）进入审查上下文。
- 所有 opt-in 的无沙箱 AI 闸门都是“信任这台机器”的声明，不是安全边界。

## 7. 后续可选决策
1. `tool` 是否按具体工具逐个加入 allow（不建议 `"*": "allow"`）。
2. 是否在真实需求出现后再扩 `sandbox.allowWrite`（当前不扩）。
3. 是否扩 Tier-1 只读白名单（逐条安全评估）。
